# GitHub 仓库与提交约定

选定仓库：https://github.com/Hdksj1/DeadLine 。实际推送状态以 Git 远程查询结果为准，不因本说明存在就认定已经上传。

## 当前目录安排

- 外层项目目录是主工作仓库，已有原始 README 提交 `c68f2e0`。
- 本地 `DeadLine/` 是独立克隆，原有初始化提交为 `00b168f`；此目录保留并加入外层忽略规则。
- 不执行 `git add .` 将嵌套仓库作为 gitlink 上传，不删除任一历史。
- 外层若与远程历史无共同祖先，先核对远程内容，再普通合并保留双方历史。不使用强推，也不覆盖未知远程内容。
- 内层副本不会自动跟随外层更新。后续开发、提交和推送均在外层主项目目录操作。

## 模块提交

当前已有功能先按真实模块整理：后端健康与解析、前端四页、复现与参赛材料。提交时间为实际入库时间，不倒填，不把现在的拆分整理描述成过去逐次提交。

以后每次：确认范围 → 实现 → 验证 → 检查 diff 与文件清单 → 提交 → 推送。真实 AI 对话与问题处理同步归档。

```powershell
git status
git diff
# 仅添加实际审阅过的路径；示例以实际改动为准
git add backend/app/notice_parser.py backend/tests/test_notice_parser.py
git diff --cached --stat
git commit -m "fix: 描述实际完成的改动"
```

在远程设置、历史衔接和上传内容确认后，推送主线：

```powershell
git push -u origin HEAD:main
```

本命令不是强推；若远程发生新提交而拒绝推送，先 fetch 检查再合并，不能用 `--force` 绕过。

## 上传前检查

- `.env`、`.venv`、`node_modules`、`dist` 和嵌套 `DeadLine/` 不得进入提交。
- `.env.example` 仅包含空凭据与公开地址。
- 检查对话材料是否包含敏感信息；原始完整材料脱敏后提供。
- 提交作者邮箱会成为历史的一部分。当前沿用既有 Git 配置；改用隐私邮箱不自动改变旧提交，不未经确认重写历史。
- 上传后在 GitHub 确认文件、提交记录及访问权限；仓库上传不代替赛事官网提交。
